# 成品级前端交付守则
界面是交付给最终用户的产品表面，不是向需求方证明完成度的实现报告。本守则约束 Agent 产出的所有用户可见前端（页面、组件、原型、邮件模板），交付标准为可直接上线。
## 核心模型：三个信息通道
界面噪声的根因是混淆读者。一次交付中存在三个通道，各自面向不同读者：
| 通道 | 读者 | 承载内容 |
|---|---|---|
| 界面 | 最终用户 | 完成操作所需的最短文字：标签、按钮、状态等功能性文字 |
| 源码注释 | 后续维护者 | 复杂逻辑、契约、TODO——写在代码里，不渲染 |
| 交付消息 | 提出需求的人 | 实现说明、技术决策、使用指引、已知限制 |
判定规则：文字进入界面前先做删除检验——删掉它，用户完成操作是否受阻。受阻则保留；不受阻则移入源码注释或交付消息，或直接删除。受阻保留的限于功能性反馈，解释性「提示」的边界见下节。
## 默认资深用户
界面默认使用者是熟悉产品的资深用户。外壳、功能入口与操作路径设计合理即自解释，不设置上手引导、教学浮层或解释性提示；信息缺口由更清晰的设计补齐，不由提示文案补齐。
此处「提示」指上手引导、教学标注与操作说教文案；表单校验、加载与错误状态、破坏性操作确认等功能性反馈照常保留（见「二、成品标准」的状态完整与交互闭环）。
## 一、界面噪声（禁用）
1. **需求复述**：把用户要求或要点列表搬进页面，如三张卡片写着「实时协作」「多端同步」「版本回溯」。
2. **功能解释与自述**：以任何人称说明实现（「本页面将调用接口获取数据」「此处展示智能分析结果」），或 AI 署名角标（「由 AI 生成」）；严禁非必要的解释性、指导性或自述性文案（如在操作入口旁附带功能说明或操作指引）；严禁在标准图标已能清晰表意时强行叠加文字。
3. **注释外漏**：TODO、「待实现」、说明性文字出现在渲染结果里；空状态写「功能开发中，敬请期待」。
4. **占位标签**：Lorem ipsum、「示例数据」「测试内容」字样贴在界面上；示例内容不具备业务语义。
5. **调试可见**：state 值、JSON、报错信息渲染进 DOM。
6. **教学浮层**：分步引导遮盖核心界面，「点击此处开始」式箭头标注。
7. **摆件交互**：点击无响应的按钮、指向 # 的链接、提交无反馈的表单。
8. **装饰堆砌**：无信息量的 emoji 标题、渐变背景、发光阴影、为填充空间而存在的图标。
9. **扁平堆砌与入口平权**：将异质、低频或系统级功能与核心高频作业同层等权平铺，将主页面做成无主次的卡片堆砌或仪表盘。
## 二、成品标准
- **文案**：按产品文案写。动词开头、短、具体，严禁非必要冗余说明：按钮是「导出报表」，不是「点击此处进行报表导出」。
- **图标优先**：语义明确的通用操作能以内联标准 SVG 清晰表意即不使用文字，存在歧义或无标准图形时才配文字；图标辅以标准 aria-label 或无侵入 tooltip，避免文字冗余破坏排版节奏。
- **Demo 纯净度**：若页面包含 Demo 辅助控制或状态切换，必须通过低视觉篇幅的独立悬浮层与业务样式解耦，禁止将演示控制代码混入业务 DOM 与原本样式。
- **数据**：无真实数据源时，填充语义成立的示例数据——人名符合真实姓名格式、数值落在业务合理区间、字段结构贴近真实接口。示例数据不带「示例」标签，除非用户要求演示场景。
- **状态完整**：空、加载、错误、成功四态覆盖。空态给出路（「暂无项目」旁放新建入口），不放解释。
- **交互闭环**：可交互元素接通行为与反馈；表单有校验与提交结果；未实现的入口不渲染，而非渲染成灰色摆设。
- **视觉克制**：一个主色、一个中性色阶、一套字体栈；层级来自间距、字重、字号，不来自彩色渐变；间距使用统一刻度（4/8px）。
- **布局可用**：不写死超出常见视口的宽度；可交互元素有可见的 hover/focus 态；使用语义化标签。
## 三、交付检验
四项检验全部通过才可交付：
1. **删除检验**：逐句检查界面文字，删除后不影响用户操作的，全部移除；解释性提示（引导、教学、操作说教）应清除，功能性反馈（校验、状态、确认）保留。
2. **生产检验**：设想页面部署在真实域名、陌生用户首次打开。此时显得突兀的元素——说明、标签、摆件按钮——即噪声。
3. **对照检验**：同类成熟产品的对应界面（表单对 Stripe、列表对 Linear、协作对飞书）不长这样的，给出保留理由，否则对齐。
4. **主路径与层次检验**：核心作业流是否清晰突出；辅助细节与低频管理是否合理分层，无突兀平铺。
## 四、边界与例外
- 实现说明与待办写在交付消息；复杂逻辑注释写在源码对应位置。两者都不进界面。
- 清理既有界面噪声时直接删除，不注释保留、不折叠隐藏。
- 用户明确要求教学页、演示标注、原型标注时，按需求交付，不受本守则限制。
- 项目已有视觉规范（设计稿、品牌色、组件库）时遵循规范，本守则只约束其中未覆盖的噪声问题。
## 交付前自查
- [ ] 界面内无需求原词、功能解释、非必要操作指引与上手引导，「示例/Demo/待实现」字样？功能性反馈（校验/状态/确认）完整保留？
- [ ] 语义明确的通用操作已优先采用标准 SVG 图标且具备无障碍标签？
- [ ] Demo 辅助控制器独立悬浮、未侵入业务 DOM 与原本样式？
- [ ] 界面主次分明，无异质/低频功能同层平铺？
- [ ] 每个按钮、链接、表单接通了行为与反馈？
- [ ] 空/加载/错误/成功四态处理完毕，空态给出路？
- [ ] 示例数据语义成立、结构贴近真实接口？
- [ ] 四项交付检验逐项执行过？

## 附录：界面与架构对照示例
| 场景 | 噪声写法 | 成品写法 |
|---|---|---|
| 扁平堆砌与入口平权 | 首页将高频作业与低频配置/成员管理/API设置平铺并列，或摊开全量表单抢占主屏 | 首屏聚焦核心作业流，低频管理与复杂配置收敛至抽屉、模态或独立设置页 |
| 需求复述 | 首页三卡片：实时协作 / 多端同步 / 版本回溯 | 直接呈现协作画布，功能在导航与使用中体现 |
| 功能解释 | 此区域将调用 API 加载待办并智能排序 | 待办列表本体 + 排序结果 |
| 操作指引 | 操作列旁附注「点击图标可直接复制或删除对应记录」 | 仅保留操作入口本身 |
| 通用操作 | 文本按钮「刷新页面」「关闭窗口」堆叠 | 标准 SVG 图标按钮并配 aria-label |
| 空态 | 这里空空如也，功能开发中~ | 输入框 + 「添加第一个任务」 |
| 未实现入口 | 置灰的分页按钮，旁注 TODO: 下一页 | 不渲染该按钮 |
| 按钮文案 | 点击此处提交您的表单信息 | 提交 |
| 首次进入 | 欢迎使用！本系统分为三大模块，请跟随引导…… | 直接进入核心界面 |
